Architecture

The final target architecture is the one described in Overview.md: Temi provides speech and camera context, MQTT carries lightweight events and commands, shared files carry image snapshots, and HermesTemiBridge is the only service allowed to validate and dispatch robot actions returned by Hermes.

Runtime roles

Component Path or endpoint Responsibility
Temi Android app com.robotemi.agent Captures ASR and camera frames; executes speak/navigation commands.
Mosquitto tcp://192.168.50.236:1883 Local event bus for both legacy and Overview topics.
Overview adapter tools/temi_overview_adapter.py Bridges the existing Android app topics to the Overview MQTT contract.
HermesTemiBridge hermes_temi_bridge/ Validates ASR event payloads, validates image files, invokes Hermes, validates actions, publishes command requests.
Hermes Agent hermes -z {prompt} Uses the temi-robot-control skill and returns JSON-only robot actions.
Legacy backend temi_backend/ Fast direct route for Temi ASR + video -> LMStudio/VLM -> legacy MQTT command.

Quick Start From Zero

Use this section when the PC and Temi are freshly restarted. Commands are written for this machine and this lab network.

0. Confirm prerequisites

cd /TemiAgent
which adb mosquitto mosquitto_pub mosquitto_sub uv hermes
ip -br addr

If system tools are missing on a fresh Ubuntu machine:

apt-get update
apt-get install -y android-tools-adb iproute2 netcat-openbsd nmap mosquitto-clients mosquitto

1. Start or verify MQTT

cd /TemiAgent
ss -ltnp | grep ':1883' || mosquitto -c /TemiAgent/mqtt/mosquitto.conf -d
nc -vz -w 3 192.168.50.236 1883

2. Connect ADB

adb disconnect 192.168.50.205:5555 || true
adb kill-server
adb start-server
adb connect 192.168.50.205:5555
adb devices -l

Healthy output:

192.168.50.205:5555    device product:rk3288 model:rk3288 device:rk3288

3. Start the Overview adapter

This service owns port 8080 for live video and converts the current Android app topics to the Overview contract. 

cd /TemiAgent/temi_backend
uv run python /TemiAgent/tools/temi_overview_adapter.py \
  --broker 192.168.50.236 \
  --port 1883 \
  --vision-port 8080 \
  --shared-root /TemiAgent/temi_shared \
  --bridge-root /TemiAgent/temi_shared

4. Start HermesTemiBridge in mock mode

Use mock mode first after every reboot. It verifies the whole Overview path without waiting on Hermes.

cd /TemiAgent/hermes_temi_bridge
MQTT_BROKER_HOST=192.168.50.236 \
MQTT_BROKER_PORT=1883 \
HERMES_INVOKE_MODE=mock \
HERMES_MOCK_RESPONSE_TEXT='Overview quick test passed.' \
TEMI_SHARED_BRIDGE_PATH=/TemiAgent/temi_shared \
TEMI_SHARED_HERMES_PATH=/TemiAgent/temi_shared \
LOG_DIR=/TemiAgent/logs/overview_bridge_mock \
uv run --extra mqtt hermes-temi-bridge --env-file /TemiAgent/hermes_temi_bridge/.env.example

5. Start the Temi app

adb shell am force-stop com.robotemi.agent
sleep 1
adb shell am start -n com.robotemi.agent/.MainActivity

6. Watch logs

Use two extra terminals while experimenting.

mosquitto_sub -h 192.168.50.236 -p 1883 -t '#' -v

adb logcat '*:I' | grep -E 'MainActivity|WebSocketClient|MqttManager|CameraManager|AgentStateMachine'

7. Trigger a mock Overview E2E test

This does not require speaking to Temi; it injects a legacy ASR message into the adapter.

python3 - <<'PY' | mosquitto_pub -h 192.168.50.236 -p 1883 -t 'temi/event/asr' -l
import json, time
print(json.dumps({
    "text": "Overview injected test",
    "language": "zh-TW",
    "timestamp_ms": int(time.time() * 1000)
}, ensure_ascii=False))
PY

Expected MQTT sequence:

temi/event/asr
temi/temi-01/asr/final
temi/temi-01/cmd/request
temi/action/speak
temi/temi-01/cmd/result

8. Switch to real Hermes

Stop the mock Bridge with Ctrl+C, keep the adapter running, then start real Hermes mode:

cd /TemiAgent/hermes_temi_bridge
MQTT_BROKER_HOST=192.168.50.236 \
MQTT_BROKER_PORT=1883 \
HERMES_INVOKE_MODE=cli \
HERMES_CLI_COMMAND='hermes -z {prompt}' \
TEMI_SHARED_BRIDGE_PATH=/TemiAgent/temi_shared \
TEMI_SHARED_HERMES_PATH=/TemiAgent/temi_shared \
HERMES_TIMEOUT_SECONDS=120 \
LOG_DIR=/TemiAgent/logs/overview_bridge_real \
uv run --extra mqtt hermes-temi-bridge --env-file /TemiAgent/hermes_temi_bridge/.env.example

For a real voice test:

mosquitto_pub -h 192.168.50.236 -p 1883 -t 'temi/action/wakeup' -m '{"source":"overview_real_hermes"}'

Speak one short sentence only, then wait. Real Hermes may take 30 to 100 seconds on the current local model/provider setup.

9. Switch to resident Hermes HTTP mode

To reduce Hermes cold-start latency, keep a Hermes AIAgent instance loaded in a local HTTP worker, then point the Bridge at that worker instead of launching hermes -z for every ASR event. 

cd /TemiAgent
python3 tools/hermes_resident_server.py \
  --host 127.0.0.1 \
  --port 8765 \
  --skill-path /TemiAgent/hermes-agent/skills/temi-robot-control/SKILL.md

curl -s http://127.0.0.1:8765/health
cd /TemiAgent/hermes_temi_bridge
MQTT_BROKER_HOST=192.168.50.236 \
MQTT_BROKER_PORT=1883 \
HERMES_INVOKE_MODE=http \
HERMES_HTTP_URL=http://127.0.0.1:8765/invoke \
TEMI_SHARED_BRIDGE_PATH=/TemiAgent/temi_shared \
TEMI_SHARED_HERMES_PATH=/TemiAgent/temi_shared \
HERMES_TIMEOUT_SECONDS=180 \
LOG_DIR=/TemiAgent/logs/overview_bridge_resident \
uv run --extra mqtt hermes-temi-bridge --env-file /TemiAgent/hermes_temi_bridge/.env.example

Compare hermes_latency_ms in /TemiAgent/logs/overview_bridge_resident/*.jsonl with the earlier CLI result.

Troubleshooting

ADB shows offline

Symptoms:

192.168.50.205:5555    offline

Fix:

adb disconnect 192.168.50.205:5555 || true
adb kill-server
adb start-server
adb connect 192.168.50.205:5555
adb devices -l

If it remains offline, unlock Temi and accept the debugging prompt. If no prompt appears, toggle wireless/USB debugging on the robot or reboot Temi.

8080 is refused

Symptoms:

nc: connect to 192.168.50.236 port 8080 failed: Connection refused

Fix: start exactly one service that owns port 8080.

pkill -f 'temi_overview_adapter.py' || true
pkill -f 'uv run temi-backend' || true
pkill -f '/TemiAgent/temi_backend/.venv/bin/temi-backend' || true

cd /TemiAgent/temi_backend
uv run python /TemiAgent/tools/temi_overview_adapter.py \
  --broker 192.168.50.236 \
  --port 1883 \
  --vision-port 8080 \
  --shared-root /TemiAgent/temi_shared \
  --bridge-root /TemiAgent/temi_shared

Temi keeps trying 192.168.50.233

This is expected with the current Android build. It has multicast configuration for both 192.168.50.233 and 192.168.50.236. The repeated failed logs for 192.168.50.233:8080 do not block this PC as long as 192.168.50.236:8080 connects and video packets continue.

Temi app feels slow or switches to knowledge skill

This usually happens when real Hermes takes longer than the Android app's 15-second WAITING watchdog. The app may time out, return to idle, or Temi's native skill UI may take focus.

Recommended mitigations:

  • Use mock Bridge for fast Overview demos.
  • Use legacy temi_backend for fast LMStudio/VLM demos.
  • Increase Android watchdog timeout if editing the Android app.
  • Use a faster Hermes model/provider or reduce prompt/tool overhead.
  • Avoid speaking a second sentence while Hermes is still processing the first event.

Bridge publishes fallback instead of Hermes action

Inspect the event log:

cat /TemiAgent/logs/overview_bridge_real/<event_id>.jsonl

Common reasons:

  • invalid_hermes_json: Hermes output had prose, terminal UI, or malformed JSON.
  • missing_image: adapter did not save readable image files.
  • navigation_target_not_allowed: Hermes chose a target outside the allowlist.
  • hermes_timeout: Hermes exceeded HERMES_TIMEOUT_SECONDS.

Android source is not available on this PC

This workspace currently does not include gradlew, settings.gradle, AndroidManifest.xml, or app/build/outputs/apk/debug/app-debug.apk. The Android app is already installed on Temi and was developed on another PC.

If the Android project is copied here, create /TemiAgent/local.properties:

ws.server.urls=ws://192.168.50.236:8080
mqtt.broker.urls=tcp://192.168.50.236:1883
mqtt.client.id=temi-agent

Then build and install:

./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
