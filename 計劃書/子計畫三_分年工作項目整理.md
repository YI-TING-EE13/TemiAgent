# 子計畫三分年工作項目整理

> Status: HISTORICAL planning material. It is not a current implementation or
> operator procedure.

> 子計畫三名稱：**多模態行為感知與緊急應變之高齡者在宅居家照護系統**
> 核心定位：以「多模態行為感知、隱私保護、邊緣 AI、緊急應變」為核心，建立可即時偵測異常、支援日常照護、生成健康報告，並能與機器人平台整合的在宅居家照護系統。

---

## 一、四年整體目標

子計畫三主要負責建立高齡者在宅照護中的「感知、判斷、記錄、通報」能力，包含：

1. **多模態異常行為偵測**：偵測跌倒、昏厥、無回應、異常表情、語音異常等事件。
2. **個人化日常提醒與智慧行程管理**：理解長者語音或模糊指令，協助安排提醒、用藥、飲水、進食與日常行程。
3. **隱私保護與資料檢索資料庫**：建立文字與影像資料庫，並進行匿名化處理與 RAG 檢索。
4. **手勢辨識與動態呼叫**：讓長者能以揮手、舉手或自定義手勢呼叫機器人或啟動功能。
5. **行為感知與智慧決策**：整合異常行為、語音、生理資訊、歷史記憶與外部知識庫，進行情境化判斷。
6. **緊急通報機制**：依事件嚴重程度進行風險分級，通知家屬或啟動 119 等緊急應變流程。
7. **個人健康報告生成**：整合生理數據、行為紀錄、異常事件與語音互動摘要，生成健康報告。
8. **模型輕量化與邊緣部署**：透過知識蒸餾、剪枝、量化等技術，讓模型可在本地或邊緣設備運行。
9. **系統整合與場域驗證**：與機器人平台、其他子計畫模組整合，並進行情境測試與使用者驗證。

## 三、第一年工作項目

### 3.1 多模態在宅居家照護異常行為偵測演算法

第一年需建立子計畫三的核心感知能力，使系統能夠偵測長者在家中可能發生的高風險事件，例如跌倒、昏厥、無回應、異常表情或痛苦語音。

主要工作包含：

1. **建立多模態異常行為偵測架構**
   - 輸入來源包含影像、語音、文字提示與生理資訊。
   - 目標是讓系統能針對居家照護情境進行異常事件理解與判斷。
   - 偵測結果需具備結構化輸出能力，方便後續通報與健康報告生成。

2. **設計視覺、語音與文字融合模型**
   - 視覺端可區分臉部表情、身體動作與互動事件。
   - 語音端可分析使用者是否有痛苦語音、求助語音或無語音回應。
   - 文字端可透過任務指令或提示語協助模型進行推理。

3. **導入少樣本學習與知識蒸餾**
   - 由於高齡者異常事件資料取得不易，需採用少量標註資料進行模型調整。
   - 可先由既有多模態模型學習基礎動作辨識能力，再針對在宅照護場景微調。

4. **輸出可解釋的異常事件資訊**
   - 表情辨識結果：例如痛苦、緊張、昏厥前異常表情。
   - 異常事件描述：例如「長者跌倒」、「手部疑似抽搐」、「無動作反應持續 30 秒」。
   - 語音摘要：例如「使用者無語音回應」、「語音內容表現痛苦」。
   - 生理資訊：例如血壓、心跳、血糖等數值。

### 3.2 具隱私保護與資料檢索功能之在宅照護資料庫

第一年需建立可長期記錄、保護隱私並支援後續檢索分析的資料庫架構。

主要工作包含：

1. **建立文字資料庫**
   - 記錄心律、血壓、用藥、喝水、進食、日常活動與異常事件摘要。
   - 可依使用者設定的週期，自動生成健康摘要。

2. **建立影像資料庫**
   - 當發生異常事件時，系統可自動儲存相關影像片段或 GIF。
   - 影像資料需與文字資料庫中的事件標籤連結，例如 `GIF_0101_0800`。

3. **導入隱私保護機制**
   - 儲存影像前需進行匿名化處理。
   - 目標是在保留表情與行為資訊的同時，避免長者身分資訊外洩。

4. **建立多模態 RAG 檢索流程**
   - 使用者或系統查詢歷史事件時，先從文字資料庫檢索。
   - 若檢索結果包含影像標籤，再連動到影像資料庫取出對應資料。
   - 最後由 VLM 或多模態模型整合文字與影像，產出具解釋性的判斷。

### 3.3 個人化日常提醒與智慧行程管理模組

第一年需建立長者日常生活支援功能，使系統不只是被動偵測異常，也能主動協助行程與生活管理。

主要工作包含：

1. **建立動態個人化情境知識圖譜**
   - 使用者檔案：年齡、性別、健康狀況、個人偏好。
   - 行為日誌：用藥紀錄、運動紀錄、飲食紀錄。
   - 即時狀態：久坐時間、心率、血壓、目前活動狀態。

2. **設計 LLM 與知識圖譜協同推理流程**
   - LLM 先理解使用者模糊指令。
   - 當資訊不足時，透過 API 查詢個人化知識圖譜。
   - 根據查詢結果生成個人化提醒或行程調整。

3. **支援模糊語意理解**
   - 例如長者說「差不多要吃了」，系統需結合時間、用藥紀錄、飲食習慣與健康狀態判斷其真正意圖。
   - 最終回應可為：「奶奶，是時候吃高血壓藥了，需要我幫您拿水杯嗎？」

## 四、第二年工作項目

### 4.1 多手勢辨識與動態呼叫技術

第二年需建立非語音互動能力，使長者在不方便說話或聽力不佳時，也能使用手勢呼叫系統。

主要工作包含：

1. **建立低功耗監測模式**
   - 系統以低幀率影像持續監測是否有手部活動。
   - 若偵測到手部活動，再喚醒完整辨識流程。
   - 目標是兼顧長時間運行與能源效率。

2. **建立主動辨識模式**
   - 被喚醒後，系統擷取高解析度影像或短影片。
   - 進行手部姿態、動作軌跡與意圖辨識。

3. **加入低光源影像增強**
   - 針對夜間、昏暗角落或居家照明不足情境進行影像增強。
   - 目標是保留手部輪廓並降低雜訊，提高辨識穩定性。

4. **開發開放集手勢辨識**
   - 不只辨識預先定義的手勢，也要支援使用者自定義或未見過的手勢。
   - 可透過手部關鍵點序列、VLM 圖像編碼器與文本描述庫進行跨模態對齊。
   - 例如將某個手勢對應到「求助」、「開燈」、「拿水」等功能描述。

### 4.2 行為感知與智慧決策模組

第二年需建立更完整的長期行為理解與決策架構。

主要工作包含：

1. **建立 Orchestrator 協調架構**
   - 任務規劃器負責理解使用者需求、分析情境並規劃行動步驟。
   - 任務執行器負責呼叫外部 API、執行函數與回報結果。
   - LLM 可透過多步驟推理進行情境判斷。

2. **整合外部資源**
   - AI 分析模型：整合第一年的異常行為偵測、子計畫一的生理分析、子計畫四的環境感知。
   - 知識庫：整合居家護理、銀髮族健康與照護建議資料。
   - 記憶庫：記錄使用者個人健康狀態、過去事件與生活習慣。
   - 數據管道：儲存中間結果，讓 LLM 可調用大型或複雜資料。

3. **建立 API 工具化介面**
   - 將偵測、查詢、通報、記憶、健康報告等功能標準化為可調用 API。
   - 讓 LLM 不直接處理所有資料，而是透過工具進行安全、可控的決策。

### 4.3 緊急通報機制

第二年需建立事件分級與應變流程。

主要工作包含：

1. **設計 Home-ESI 風險分級標準**
   - L1：高風險異常，可能有立即生命威脅，例如跌倒後意識喪失、呼吸停止。
   - L2：中度異常或慢性病警示，例如長期不活動、持續劇烈咳嗽、需主動關懷與趨勢記錄。
   - L3：輕度行為異常但短期內無立即安全顧慮，例如作息紊亂、情緒低落。

2. **建立多步驟資訊蒐集流程**
   - 即時感知：姿態、表情、語音狀態。
   - 生理數據：心率、血壓等。
   - 歷史記憶：病史、近期行為模式。
   - 語音互動：直接詢問使用者主觀感受與意識狀態。

3. **建立對應處置策略**
   - L1：立即通報 119、通知家屬、傳送即時資訊摘要並記錄事件。
   - L2：語音關懷、提供建議、通知家屬並記錄事件。
   - L3：提供情感陪伴或提醒，持續觀察並記錄，必要時升級為 L2。

### 4.4 智慧化個人健康報告生成

第二年需建立健康報告模板與自動生成流程。

主要工作包含：

1. **整合多模態紀錄**
   - 異常事件描述。
   - 表情辨識結果。
   - 語音互動摘要。
   - 生理資訊數值。
   - 飲食、用藥、作息紀錄。

2. **設計個人健康報告模板**
   - 報告期間總覽。
   - 異常事件記錄。
   - 行為紀錄摘要。
   - 生理資訊趨勢摘要。
   - 風險等級與通報紀錄。

3. **結合 RAG 與記憶層 API**
   - 從歷史資料庫檢索相關紀錄。
   - 將多筆結構化資訊整合為可讀、具摘要性與照護價值的健康報告。

## 五、第三年工作項目

### 5.1 模型輕量化與知識蒸餾

第三年需將前兩年建立的多模態模型轉向可部署、可運行、可驗證的系統版本。

主要工作包含：

1. **進行模型輕量化**
   - 採用知識蒸餾，將大型 Teacher Model 的能力轉移至較小的 Student Model。
   - 採用剪枝、量化等方式降低模型大小與運算成本。
   - 目標是在不大幅犧牲效能的前提下，提升本地推論能力。

2. **建立邊緣 AI 部署規劃**
   - 評估本地伺服器、機器人平台或嵌入式硬體的算力需求。
   - 規劃模型在本地端推論，降低敏感資料上傳雲端的風險。
   - 平衡推論速度、準確率、記憶體需求與硬體限制。

3. **建立性能評估機制**
   - 評估異常行為偵測準確率。
   - 評估手勢辨識與互動延遲。
   - 評估緊急通報反應時間。
   - 評估健康報告生成合理性。

### 5.2 既有機器人平台初步整合與驗證

第三年需將子計畫三功能初步整合至機器人平台上進行測試。

主要工作包含：

1. **整合感測與互動元件**
   - 攝影機。
   - 麥克風陣列。
   - 揚聲器。
   - 平板介面。
   - 移動底盤或既有機器人互動元件。

2. **實作核心照護功能**
   - 即時異常行為偵測。
   - 分級緊急通報。
   - 個人化行程提醒。
   - 手勢辨識。
   - 平板視訊互動或健康報告顯示。

3. **建立標準化測試情境**
   - F1：跌倒或異常事件觸發緊急通報。
   - F2：新增日常提醒並確認準時提醒。
   - F3：手勢互動觸發機器人回應。
   - F4：記憶演化驗證，例如高血壓與血糖偏高資訊整合。
   - F5：無異常情境下健康報告生成驗證。

4. **建立評估指標**
   - Precision、Recall、F1-score、ROC-AUC。
   - 異常事件偵測到家屬通知之間的通報延遲。
   - 系統可用性量表（SUS）。
   - 語音回應邏輯性與親和力。
   - 誤觸發率與互動自然度。

## 六、第四年工作項目

### 6.1 系統整合與架構優化

第四年需將子計畫三由「模組驗證」推進到「整體系統驗證」。

主要工作包含：

1. **完成行為感知與緊急應變系統邊緣部署**
   - 將異常行為偵測、手勢辨識、行為感知、智慧決策與緊急通報整合為完整系統。
   - 優化模型推論速度與系統穩定性。
   - 確保資料可在本地或邊緣端安全處理。

2. **跨系統通訊介面整合**
   - 與子計畫一的生理訊號模組串接。
   - 與子計畫二的中文互動與關懷回應模組串接。
   - 與子計畫四的環境感知與巡檢模組串接。
   - 與子計畫五的機器人平台與硬體控制模組串接。

3. **建立完整情境流程**
   - 異常事件偵測。
   - 生理與行為資訊整合。
   - 風險分級。
   - 語音互動確認。
   - 家屬或 119 通報。
   - 事件紀錄。
   - 健康報告生成。

### 6.2 場域與應用情境驗證

第四年需進行應用情境測試與使用者回饋收集。

主要工作包含：

1. **規劃場域測試情境**
   - 跌倒或昏厥事件。
   - 長時間無動作或無回應。
   - 用藥提醒與生活行程提醒。
   - 手勢呼叫機器人。
   - 異常事件後自動健康報告。
   - 家屬通知與緊急通報流程。

2. **執行使用者測試**
   - 測試系統是否能被高齡者理解與使用。
   - 評估提醒、通報與互動流程是否自然。
   - 收集長者、家屬、照護者或場域人員回饋。

3. **完成系統優化**
   - 根據測試結果調整模型參數。
   - 修正誤判與漏判問題。
   - 優化語音回應內容。
   - 改善通報流程與使用者介面。
   - 提升整體穩定性與滿意度。

## 七、可以用來向老師或團隊說明的精簡版本

子計畫三四年的發展邏輯可以整理為：

- **第一年：建立核心能力**
  建立多模態異常行為偵測、個人化智慧助理與隱私保護資料庫，先讓系統能感知、記錄與理解在宅照護情境。

- **第二年：擴充互動與決策能力**
  加入手勢辨識、動態呼叫、行為感知、智慧決策、緊急通報與健康報告生成，使系統能從單純偵測進一步走向照護決策與應變。

- **第三年：進行輕量化與平台驗證**
  透過知識蒸餾、剪枝與量化將模型輕量化，並初步整合至既有機器人平台，驗證異常偵測、提醒、手勢互動、通報與報告生成等功能。

- **第四年：完成整合與場域驗證**
  完成邊緣部署、跨子計畫系統整合與場域測試，依使用者回饋優化模型、流程與介面，形成可落地的在宅照護行為感知與緊急應變系統。
