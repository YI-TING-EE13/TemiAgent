# Benchmark 測試工具

最後更新日期：2026-11-11。

## 簡介

這組 benchmark 使用固定的對話測資，觀察小安的回答、action 選擇與回覆速度。
目前有兩項測試：

- **Action 一致性**：回答需要使用者回應時，是否選用正確的 action。
- **Reasoning 速度與回答**：在目前已載入的模型上，觀察不同 reasoning effort 的耗時與回答差異。

兩項測試共用相同測資，方便重複實驗；本工具不負責跨模型比較或切換模型。

兩個測試的執行指令，請看 [測試執行方式](RUN_TESTS.md)。

## 1. Action 一致性測試

**目的：確認回答內容與 action 的選擇一致。**

| 回答情況 | 應使用的 action |
|---|---|
| 需要使用者接著回答 | `ask_clarification` |
| 完整陳述，不需要使用者回答 | `speak` |

每筆結果會列出實際回答、action 與一致性判定。目前採文字規則輔助判定，
仍需人工檢查，不能直接當作回答品質的評分。

可選擇只跑一筆或全部 23 筆。若啟用測試記憶清理，會先備份，再精準移除本次事件的資料；
遇到歸屬不明或檔案同時被修改時會停止，不會全面刪除其他記憶。

## 2. Reasoning 速度與回答比較

**目的：固定目前已載入的模型，只觀察 reasoning effort 改變帶來的差異。**

工具會自動記錄目前的模型、context 與 Resident 使用的 effort，不需要另填模型名稱。
每次量測一個目前正在運行的 effort；要測另一個 effort，先透過既有啟動流程變更設定，
再用相同測資重跑。工具不會自行切換模型、修改 effort 或重啟服務。

例如在同一個模型下分別測試 default 與 none，檢查：

- 平均、中位數及較慢案例的回覆時間。
- 每筆回答文字與 action 是否改變。
- 是否出現錯誤或退回預設回答。

其中 default 表示沿用 provider 預設，不保證 thinking 一定開啟。
比較 effort 時應保持測資、context、功能設定與硬體負載一致，並關閉對話 Context 原型與照護記憶檢索。

### 時間與結果怎麼看

| 項目 | 意義 |
|---|---|
| Hermes 耗時 | Bridge 呼叫 Resident 到取得完整推理回覆的時間。 |
| 指令產生耗時 | 從送出測試事件，到觀察端收到對應指令的時間。 |
| 有效輸出數 | 排除錯誤、fallback、未通過驗證等結果後的筆數。 |
| 回覆與 action 一致性 | 回答是否需要回應，與選用的 action 是否相符。 |

時間不包含真實語音辨識或 Temi 說話，也不是模型第一個 token 的等待時間。
Warmup（暖機）結果會保留，但不納入正式統計；失敗與 fallback 不會因為很快就被當成有效樣本。

結果預設保存在 `logs/benchmarks/`，每次執行各有獨立目錄，包含實驗設定、
逐筆輸入／回答／action／耗時、表格匯出與摘要。沒有自動語意品質評分，
有效輸出也不等於內容正確或機器人執行成功。

## 執行前注意

預設離線模式只檢查測資，不呼叫模型。Live 測試需要先準備並授權使用既有環境；
在線的 Temi 可能實際說話，測試也可能寫入記憶，請避免與正式照護互動同時進行。

測試輸出可能含私人環境的內容，分享前應先檢查；逾時或清理被拒絕時，先確認狀態再重試。
連線設定與完整操作選項可查看各工具的 `--help`。
